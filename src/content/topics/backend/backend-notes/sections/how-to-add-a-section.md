## 目录结构

```text
src/content/topics/backend/backend-notes/
├── topic.md              # 专栏介绍：封面、简介、标签
└── sections/             # 专栏里的每一节，一节 = 一个 md 文件
    └── how-to-add-a-section.md
```

## 新增一节

1. 在 `sections/` 下新建一个 `.md`，文件名用英文小写加连字符，它会成为这一节的链接地址。
2. 文件开头必须有 frontmatter：`title` 和 `order` 是必填，`readTime` 可选。

```markdown
---
title: 这一节的标题
order: 2
readTime: 8 分钟
---

正文用 Markdown 写，支持代码块、表格、列表和图片。
```

3. `order` 决定目录和“上一节 / 下一节”的顺序，不用把文件名带上编号。

## 本地预览与上线

改完先本地看效果，确认没问题再提交，提交后 GitHub Actions 会自动重新构建上线：

```bash
npm run validate:content   # 校验 frontmatter、重复 slug、空正文
npm run check:markdown     # 渲染冒烟检查：代码高亮、语言标注、LaTeX 公式
npm run dev                # 本地预览 http://localhost:5173
git add src/content && git commit -m "Add backend column section" && git push
```

## 正文能写什么

- **代码块**：围栏标注语言，代码块左上角会显示语言名，右上角有复制按钮，并按语言着色。

  `````markdown
  ```c++
  int main() { return 0; }
  ```
  `````

  语言名支持带符号的写法（`c++`、`c#`、`objective-c` 都能正确显示）。
  **一定要标语言**：不标语言的围栏不会渲染成代码块（已知限制），纯文本也请写 ```` ```text ````。

- **数学公式**：行内用 `$...$`，独立成行用 `$$...$$`，由 KaTeX 渲染。

  ```markdown
  行内 $E = mc^2$，块级：

  $$
  \sum_{i=1}^{n} i = \frac{n(n+1)}{2}
  $$
  ```

  正文里真要写美元符号要转义成 `\$`，否则两个 `$` 之间的内容会被当成公式。

- **表格、任务列表、删除线**：GFM 语法，正常写。
- **图片**：文件放到 `public/`，正文用 `/my-blog-P5R/文件名` 引用。

## 小节骨架（直接复制这段）

以后每一节都按这个骨架写。四个段落不是形式主义，它们决定了这条笔记以后能不能被复现、能不能蒸馏成 Skill：

| 段落 | 它的作用 |
| --- | --- |
| 前置条件 | 换台机器 / 换个环境时，能不能从零跑起来 |
| 步骤 | 以后照着做就能复现，不用重新查资料 |
| 验证 | 一条命令或一个预期输出，证明真的跑通了 |
| 踩坑 | 卡住过一次的地方，别卡第二次 |

````markdown
---
title: 这一节的标题
order: 2
readTime: 8 分钟
---

一句话说明这一节要解决什么问题、跑完能得到什么。
````

## 写作约定

- 一节只讲一个主题，太长了就拆两节，目录会更清楚。
- 命令、配置、报错日志原样贴，不要改写，也不要用截图代替。
- 版本号写清楚，后端的东西换个版本结论就可能不一样。
